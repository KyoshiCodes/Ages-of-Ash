## Private-no-dns rehearsal boundary

The first proposed OCI mode is private-no-dns. It requires an administration-only Bastion path, no public host IP or ingress, separate runtime/backup/release identities and the same explicit migration and empty-target restore approvals. Public DNS/TLS, browser/WebSocket security-edge behavior and public alert delivery are **deferred**, not validated by a private probe. The checked-in public host provisioner opens 80/443 and must not be used for this mode. Local disposable backup/restore parity remains verified in Windows and hosted CI; it does not become off-host recovery merely because a private OCI plan passes. An off-host claim needs a selected free/approved remote target, encrypted transfer, independent key custodian and actual retrieval/empty-target restore evidence. Operators must confirm current Always Free eligibility and a $0 planned estimate in OCI Console before any later resource creation; no billing guarantee or recovery target is inferred. Named recovery ownership and populated-target refusal remain required.

The daily `ages-backup.timer` invokes `deploy/backup.mjs` as Unix `ages-backup` with PostgreSQL role `ages_backup` (read-only `pg_read_all_data`, no write). It writes an atomic custom-format dump under `/var/backups/ages` and retains seven local files. A local copy does not survive host or volume loss. The operator must verify nonempty size/checksum, encrypt with the public age recipient, upload ciphertext off-host using a backup-only OCI API-key profile, and prove denied read/decrypt and successful independent retrieval/decrypt on an isolated recovery host. The decrypt identity never lives on the source VM or in Object Storage. Rotate/revoke the backup profile or key after compromise under the named owner.
