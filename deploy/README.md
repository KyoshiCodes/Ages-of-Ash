# Oracle Ampere deployment

Use an Ubuntu 24.04 ARM64 instance with a reserved public address and DNS A record. Local work remains native Windows. Check current free-tier quotas in your account; no paid resources are assumed.

1. OCI has **two network gates**: add inbound TCP 80 and 443 to the subnet VCN security list (or attached NSG), AND allow them through the instance INPUT chain. Provisioning inserts these rules before Oracle's reject rule and persists them with iptables-persistent / netfilter-persistent. Keep SSH limited to your administration address. Never open 3000 or 5432. Do not publish an AAAA record unless IPv6 routes and both firewalls are configured.
2. Connect using Windows OpenSSH: `ssh ubuntu@YOUR_IP`. Run `sudo apt-get update`, then `sudo apt-get install -y nodejs git`. This initial Node bootstraps the provisioner, which installs Node 24 from the signed NodeSource apt repository.
3. Clone the repository with `git clone https://github.com/KyoshiCodes/Ages-of-Ash.git`. From its directory run `sudo node deploy/provision.mjs game.example.com`. The script installs signed PostgreSQL 18 packages, Caddy and pnpm, creates the ages service user and unit files. Package installation may ask about firewall persistence; accept saving current rules. Provisioning is safe to rerun and preserves existing environment configuration.
4. Use `sudo -u postgres psql` to run `CREATE ROLE ages LOGIN PASSWORD 'YOUR_RANDOM_PASSWORD';` and `CREATE DATABASE ages OWNER ages;` once. Exit psql using `\q`. Edit `/etc/ages/ages.env` with `sudoedit`; URL-encode the password in DATABASE_URL. PostgreSQL must use scram-sha-256 for localhost TCP and listen only locally. Remove any development credentials.
5. Run `sudo node deploy/release.mjs` from the cloned repository. It fetches canonical main into an immutable release, installs, checks, builds and applies migrations before atomically swapping the current symlink. Run the seed once using `sudo systemd-run --wait --pipe -p User=ages -p WorkingDirectory=/srv/ages/current -p EnvironmentFile=/etc/ages/ages.env /usr/bin/pnpm db:seed`, then restart the worker with `sudo systemctl restart ages-worker`.
6. Open your HTTPS domain. Confirm registration, an operation, live update, and `https://YOUR_DOMAIN/api/health`. Future deployments: from Windows run `./deploy/deploy.ps1 -RemoteHost ubuntu@YOUR_IP`.

There is a short API restart window, usually seconds. WebSockets reconnect and snapshots recover. This is not zero downtime. Only additive, backward-compatible migrations qualify for code rollback; restore a backup into a separate database if a destructive migration needs reversal. Old releases are retained deliberately; prune approved old worktrees with git after checking the current symlink.

Logs: `sudo journalctl -u ages-api -u ages-worker --since today`; follow with `sudo journalctl -u ages-api -f`. Set journald SystemMaxUse=200M in `/etc/systemd/journald.conf` and restart journald to cap local log storage. Health probes return database connectivity, not worker freshness; monitor worker journal and ranking update cadence.

Backups: `sudo systemctl start ages-backup` and `sudo systemctl list-timers ages-backup.timer`. Seven custom-format dumps are retained under `/var/backups/ages` with restrictive permissions. Copy encrypted backups off-host; local disk loss otherwise loses both data and backups. Restore to a newly created empty database with DATABASE_URL set to that target: `node deploy/restore.mjs /path/backup.dump --confirm-empty-target`. Verify counts and login before changing the service environment; rehearse this before public launch.

ARM64 dependency risk: argon2 uses native prebuilds; validate availability on Ubuntu aarch64. Prisma's schema engine, Vite/Rolldown, Tailwind oxide and esbuild have platform binaries. Build on the instance, never copy Windows node_modules. If argon2 lacks a matching binary, install Ubuntu build-essential and python3 for its source build; this is a production-host-only toolchain. The Prisma runtime uses the JavaScript pg adapter. Budget 2 GB of free RAM for installation/build; avoid simultaneous builds and database maintenance.
